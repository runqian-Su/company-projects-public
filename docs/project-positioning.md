# 项目定位矩阵

## 总体定位

2026.04-2026.07 三个月内，这些项目在业务交付环境中并行推进。它们共同指向一个能力画像：

```text
业务理解 + 结构建模 + AI 协作实现 + 运行验收 + 脱敏表达
```

## 项目矩阵

| 项目 | 主要问题 | 核心设计 | 能力证明 |
| --- | --- | --- | --- |
| BPO 数据平台 | 多项目数据如何从原始处理进入可信交付 | A/B/Ba/C 分层、Ba 任务作为最高业务操作抽象、diff/apply/build/publish | 企业系统架构、数据治理、操作安全 |
| 财务应收对象库 | 行级财务明细如何变成可汇总对象 | 集团、主体、往来对象、单据、事实 | 对象建模、财务口径一致性 |
| 招投标 Agent 工作流 | 分散公开信息如何进入可控 Agent 流程 | 多 Skill 串联、worker 集群、硬门控、去重 | Agent 编排、质量控制、并行任务组织 |
| 考勤脏数据管线 | 多来源 Excel 和隐含规则如何收敛 | 文件/sheet 探测、身份归一、白名单、异常归因 | 脏数据处理、传统企业交付 |
| 方案生成 Skill | AI 方案输出如何保持风格和事实一致 | 资产库、模板库、结构模式、deck JSON、校验 | 受约束内容生产、幻觉控制 |
| 猎头报告 Skill | 推荐报告如何降低输出漂移 | resume.raw、insight、report.json、模板渲染 | AI 前端自动化、标准化报告对象 |

## 主次关系

主项目建议阅读顺序：

1. BPO：先看系统架构和数据治理；
2. 财务：再看对象建模；
3. 招投标：再看 Agent 编排；
4. 考勤：补充脏数据处理能力。

补充项目：

- 方案生成：更偏 AI 产品化和内容工作流；
- 猎头报告：更偏标准格式约束 AI 输出，不作为核心技术案例。
