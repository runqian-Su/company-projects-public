# 作品集总览

## 时间与工作方式

本项目集对应 2026.04-2026.07 三个月内并行推进的一组企业内部项目。

这些项目覆盖 BPO 数据平台、财务应收对象库、招投标 Agent 工作流、集团考勤处理、政企营销方案生成和猎头推荐报告生成。它们不是同一条技术路线的重复练习，而是在不同业务问题中反复使用同一套 AI-native 工作方式：

```text
理解业务问题
  -> 建立对象、事实、流程和规则
  -> 定义最小可运行闭环
  -> 借助 AI 快速实现
  -> 通过真实运行结果持续修正
  -> 脱敏抽象为公开 Demo
```

## 项目层级

主案例：

- `bpo-data-platform`：最能体现企业现代业务系统架构、数据治理和受控操作层设计；
- `finance-ar-object-platform`：最能体现业务对象建模和财务口径一致性；
- `tender-agent-workflow`：最能体现 Agent 编排、多 Skill 协同和集群 worker 汇总；
- `attendance-dirty-data-pipeline`：最能体现传统企业脏数据处理和异常归因。

补充案例：

- `proposal-generation-skill`：体现受约束内容生产、资产库和模板化生成；
- `talent-report-skill`：体现标准化报告对象和 AI 作为前端自动化的轻量工具链。

## 这组项目证明什么

这组项目证明的不是单一框架熟练度，而是：

- 能从复杂业务里识别真正需要建模的对象、状态和流程；
- 能把 AI 用在结构化研发与运行验证中，而不是只生成一次性文本；
- 能在多个陌生场景中快速形成可运行、可验收的系统雏形；
- 能区分主系统、工具链、Demo、补充案例之间的轻重；
- 能在公开展示时主动控制脱敏边界和能力表达边界。

## 能力边界

这些公开 Demo 不是完整生产系统，也不包含真实业务数据。它们的作用是展示项目背后的结构设计和关键机制。

其中 BPO、财务、招投标和考勤更适合作为主要讨论对象；方案生成和猎头报告更适合作为 AI 工具化与标准化输出的补充案例。
