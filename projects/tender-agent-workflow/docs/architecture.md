# 两代 Agent 编排说明

## V1：多 Skill 串联

V1 的核心思想是把一条招投标线索链路拆成多个 Skill：

```text
公开来源发现
  -> 标题/详情硬门控
  -> 固定字段抽取
  -> 能力匹配分析
  -> 推送预览或交付
```

每个 Skill 只负责自己的阶段：

- discovery 只负责候选发现、硬门控和去重；
- field extract 只负责详情页字段抽取和质量标记；
- analysis 只负责匹配评分和优先级；
- push/delivery 只负责把已分析结果转成可交付格式；
- orchestrator 只负责调度、状态、报告和失败处理。

这个结构避免了单个 Agent 同时负责搜索、判断、抽字段、打分和发送，从而降低幻觉和误操作风险。

## V2：Agent 集群

V2 的核心思想是把不同来源、关键词或策略交给多个 worker agent 并行处理。

```text
主 agent
  -> worker A：公开来源 / 核心关键词
  -> worker B：公开来源 / 扩展关键词
  -> worker C：行业来源 / 区域策略
  -> worker A1：浏览器视觉线 / 登录态或复杂 DOM
  -> 汇总去重
  -> 交付预览
```

主 agent 不直接抓网站、不抽字段、不改 worker 的固定能力。它只负责：

- 传递本轮任务参数；
- 收集各 worker 的标准 JSON；
- 对跨 worker 结果去重；
- 识别失败 worker；
- 生成最终交付预览和集群报告。

## 为什么需要两版

V1 适合把链路做清楚：每一步的输入、输出、门控和报告都稳定。

V2 适合扩大覆盖面：多个 worker 可以并行跑不同来源或策略，主 agent 只处理合流和交付。这一版证明的是 Agent 编排能力，而不是单点脚本能力。

## 治理边界

本 Demo 保留以下治理规则：

- 编排层不绕过硬门控；
- 写操作只写 runtime 目录；
- 真实推送不在 Demo 中实现；
- 失败 worker 会进入报告，不被静默吞掉；
- 去重以后才生成交付预览；
- 所有输入和输出均为脱敏合成内容。
