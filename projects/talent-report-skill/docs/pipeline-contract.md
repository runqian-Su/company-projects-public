# 推荐报告链路契约

## 分层对象

```text
resume.raw.json：事实层
  候选人的基础信息、教育经历、工作经历和项目事实。

transcript.json：转写层
  访谈或音频的文本化结果。公开 Demo 中不实现真实转写。

insight.json：洞察层
  基于事实和访谈整理出的优势、风险、岗位匹配判断。

report.json：展示层
  最终推荐报告对象，也是模板渲染唯一正式输入。
```

## 为什么要有 report.json

如果直接让 AI 输出 Word 文稿，常见问题是：

- 格式每次不同；
- 字段缺失或顺序漂移；
- 推荐理由可能混入未证实判断；
- 渲染器无法稳定复用；
- 人工难以复核每段内容来源。

因此链路要求先生成标准 `report.json`，再由模板渲染器消费。

## 关键约束

- `resume.raw.json` 是硬事实来源；
- `insight.json` 是分析来源，不等于最终文案；
- `report.json` 不得编造公司、日期、职位、学历、薪资、业绩数字；
- 未提供目标岗位时，推荐岗位和推荐理由必须留空；
- 渲染器只能读取 `report.json`，不能绕过它直接读取简历或洞察。

这个项目的价值不在复杂算法，而在把 AI 输出放进一个稳定的数据契约里。
