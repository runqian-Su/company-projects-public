# 多层对象模型说明

## 为什么不是一张表

应收账款分析如果只停留在行级表格，会很难回答这些问题：

- 某个主体下有哪些往来对象？
- 某个往来对象下有哪些单据号对象？
- 哪些单据号对象存在余额？
- 命中的单据号对象下有哪些明细行？
- 集团、主体、往来对象、单据号的余额是否一致？

因此，本 Demo 将原始明细抽象为对象库。

## 对象层级

```text
L1：集团
  组织集合，例如 DemoCorp Group。

L2：主体
  会计主体，例如 Demo Entity A。

L3：往来对象
  某主体下的客户对象。

L4：单据号对象
  某主体、某客户下的一张应收来源单据。

Fact：应收余额事实
  挂在 L4 单据号对象上的分析事实。
```

对象和事实的区别：

```text
对象回答“分析对象是谁”。
事实回答“这个对象在某个时间点有什么指标”。
```

## 对象级命中、明细级展开

本 Demo 的核心口径：

```text
先按 L4 单据号对象判断是否命中；
命中后，再展开该对象下全部明细。
```

示例：

```text
Demo Entity A + Customer Alpha + AR-2026-001
  行 1：余额 1200
  行 2：余额 0

结果：
  AR-2026-001 命中；
  行 1 和行 2 都进入事实明细。
```

这样可以避免把属于同一单据号对象的上下文行误删。

## 一致性验证

对象库必须满足：

```text
集团余额
  = 主体余额汇总
  = 往来对象余额汇总
  = 单据号余额汇总
```

如果这些口径不一致，说明对象生成、事实挂载或汇总查询中至少有一处出现问题。
