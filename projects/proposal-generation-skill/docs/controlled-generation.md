# 受约束方案生成说明

## 为什么不是自由生成

营销方案如果完全交给模型自由写，常见问题是：

- 风格不稳定：每次语气、章节和页面密度都不同；
- 内容漂移：公司介绍、资质、案例容易被改写或编造；
- 结构失控：章节顺序、目录和正文页面对不上；
- 渲染不稳：模板字段缺失、本地图片不存在、页数不一致；
- 复核困难：不知道每一页内容来自资产库、行业库还是模型临时生成。

因此，本项目把模型的自由度限制在结构化框架内。

## 核心机制

```text
资产库：固定可复用事实和证明材料。
模板库：固定页面类型、字段和视觉框架。
结构模式：固定常用方案的章节顺序和页面清单。
行业叙述库：固定行业痛点、服务模块、流程和案例来源。
deck JSON：把方案转成可校验的结构化中间产物。
validate：渲染前检查引用、章节、字段和来源。
render report：渲染后记录输出文件、页数和错误。
```

## 降低幻觉的方式

- 公司类页面必须引用 asset registry，不允许临时改写公司事实；
- 行业页必须引用 industry narrative，不允许凭空补行业案例和规模数据；
- 图示页只能使用已登记 diagram/template 类型；
- deck 里每页必须声明 `source_type`，例如 `asset`、`industry_narrative`、`manual_input`；
- validate 会检查缺资产、缺模板、章节和目录不一致；
- 未登记内容不会静默通过。

## 降低执行不稳定的方式

- 所有页面先生成 deck JSON，再统一渲染；
- 模板字段契约固定，减少渲染时缺字段；
- 资产和模板都通过 registry 引用，不扫描目录猜用途；
- validate-only 可以在没有浏览器/PDF 环境时先检查结构；
- render report 记录输出路径、页数和错误，方便复盘。
